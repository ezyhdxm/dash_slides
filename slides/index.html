1 · Why a server

Plotly vs Dash

3:00–6:00. The key picture of the talk. Left: Python's job ends when the file is written; any new question means re-running the script. Right: the server stays up. The browser holds the page and every widget's value; when something that matters changes it sends a small request, and Python answers with new content for parts of the page.
2 · Building a page

The smallest Dash app


from dash import Dash, html, dcc
import plotly.express as px
from data import bonds

app = Dash(__name__)

fig = px.scatter(bonds, x="maturity", y="spread", color="sector")

app.layout = html.Div([
    html.H1("Corporate bonds"),
    html.P(f"{len(bonds)} bonds"),
    dcc.Graph(id="chart", figure=fig),  # id: find it later
])

if __name__ == "__main__":
    app.run(debug=True)     # http://127.0.0.1:8050
Components nest like boxes: the order in the code is the order on the page. An id lets the app find a component later, to read it or update it.

3 · Callbacks

A callback: "when this changes, run that"

app.layout = html.Div([
    html.H1("Corporate bonds"),
    dcc.Dropdown(sectors, "Banks", id="sector"),
    dcc.Checklist(ratings, ["A", "BBB"], id="rating"),
    html.P(id="summary"),
    dcc.Graph(id="chart"),
])

@callback(Output("summary", "children"),
          Output("chart", "figure"),
          Input("sector", "value"),
          Input("rating", "value"))
def update(sector, ratings):
    d = bonds[(bonds.sector == sector)
              & bonds.rating.isin(ratings)]
    text = f"{len(d)} bonds, avg {d.spread.mean():.0f} bp"
    fig = px.scatter(d, x="maturity", y="spread")
    return text, fig
Inputs → arguments, in order. The first Input arrives as the first argument (sector), the second as the second (ratings).
Return values → Outputs, in order. text fills the first Output, fig the second.
13:00–15:30. Steps 1–2: each Input and the argument it becomes. Steps 3–4: each returned value and the Output it fills. The names don't have to match; only the order counts. The code here is shortened: the demo file also handles "no bonds match" and prints a line for every call (with run_all.py, those lines go to demos/.04_callback.log; run python 04_callback.py in a terminal to show them live).
3 · Callbacks, behind the scenes

How the browser hands the work back to Python

15:30–17:30. Walk 1 to 5. If asked: the browser learns which inputs belong to which callback when the page first loads. Each request carries every input value the function needs, so the server keeps no memory between requests. The new chart travels as data each time, so keep returned charts lean. To show it live, open DevTools → Network in the Live app on the previous slide: each change is one POST to /_dash-update-component.
3 · Click to drill down

Click a bond, see its history


overview = px.scatter(bonds, x="maturity", y="spread",
                      color="rating", hover_name="issuer",
                      custom_data=["cusip"])   # rides along with each point

app.layout = html.Div([
    dcc.Graph(id="overview", figure=overview),
    dcc.Graph(id="detail"),
])

@callback(Output("detail", "figure"),
          Input("overview", "clickData"))
def show_history(click):
    if click is None:                     # page load: nothing clicked
        cusip = bonds.cusip.iloc[0]
    else:
        cusip = click["points"][0]["customdata"][0]
    h = history[history.cusip == cusip]
    return px.line(h, x="date", y="spread", title=cusip)
demos/05_drilldown.py
17:30–20:00. The trick is custom_data: attach the key you need (cusip) to every point, and the click sends it back. Behind the scenes, a click is just another change the browser reports: the chart's clickData changes, it is an Input, so the same round trip as the last slide runs. Using x/y to find the bond would be fragile.
